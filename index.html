Question 1 · Remembering

Characteristics of a Modern Computer and Five Generations

Primary characteristics

  • Speed: Performs millions or billions of operations in a short time.
  • Accuracy: Produces correct results when the data and instructions are correct.
  • Diligence: Can repeat tasks without becoming tired.
  • Storage: Stores large amounts of data and retrieves it quickly.
  • Automation: Works automatically after receiving instructions.
  • Versatility: Supports many tasks, such as calculations, communication, design and record keeping.
  • Reliability: Produces consistent results when functioning correctly.

Five generations of computers

GenerationMain technologyKey features / examples
First (c. 1940–1956)Vacuum tubesVery large, hot, expensive and power-hungry; e.g., ENIAC.
Second (c. 1956–1963)TransistorsSmaller, faster and more reliable than first-generation machines.
Third (c. 1964–1971)Integrated circuits (ICs)Improved processing and reduced size and cost.

Fifth (current and developing)Artificial intelligence and advanced parallel processingFocus on learning systems, natural-language processing and intelligent applications.

Question 2 · Understanding

Block Diagram and Working of a Computer

A computer accepts data through input devices, processes it according to instructions, stores data when needed, and presents the result through output devices. The CPU coordinates these operations.

Basic functional block diagram
Input UnitKeyboard, scanner
→
CPUControl Unit + ALU + registers
→
Output UnitMonitor, printer
↕
Memory / StorageRAM, ROM, SSD or hard drive

Main components

  • Input unit: Converts user actions or physical data into a form the computer can process.
  • CPU (Central Processing Unit): Executes instructions. The Control Unit (CU) directs operations, while the Arithmetic Logic Unit (ALU) performs calculations and logical comparisons. Registers hold small amounts of data for immediate use.
  • Memory unit: RAM temporarily holds active programs and data; ROM stores essential firmware. Secondary storage keeps files for longer periods.
  • Output unit: Presents processed information in visual, printed or audio form.
  • I/O interface: Controllers and ports connect peripheral devices to the system. Data may travel over buses; control signals coordinate when operations occur.

Flow of data, instructions and control

  1. A program and data are loaded into memory.
  2. The CPU fetches an instruction from memory.
  3. The Control Unit decodes the instruction and coordinates data movement.
  4. The ALU or another CPU unit executes the instruction.
  5. The result is stored in a register or memory and sent to an output device when required.
Remember: Data and instructions move through buses and interfaces; control signals tell components when and how to perform their tasks.
Question 3 · Applying

Use of Optical Scanning and Electronic Card Readers on Campus

Optical scanners read printed marks or patterns, while electronic card readers identify a card using a barcode, magnetic stripe, smart chip or contactless technology. These devices can reduce manual entry and improve record keeping.

Examples of campus use

1. Attendance

A student presents an ID card at the entrance. The reader captures the ID and sends it to the attendance system, which records the time after checking the student record.

2. Library checkout

The librarian scans a book barcode and the student's card. The library system checks the account and updates the book's loan status.

3. OMR examinations

An Optical Mark Recognition (OMR) scanner detects filled bubbles on answer sheets and transfers the responses to marking software.

4. Document processing

A scanner captures forms or printed pages as digital images; OCR software may convert printed text into searchable text.

Example: library checkout workflow
Scan student ID card
↓
Scan book barcode
↓
Library system checks account and book status
↓
Loan record updated · due date displayed

Benefits and precautions

  • Faster processing and fewer manual typing errors.
  • Searchable, consistent records and easier reporting.
  • Use access controls, backups and secure storage for student data.
  • Keep a manual alternative for damaged cards, scanner failures or accessibility needs.

Low-Level and High-Level Programming Languages

Programming languages allow people to give instructions to computers. They differ in how closely they relate to hardware and how easy they are for humans to read and maintain.

BasisLow-level languagesHigh-level languages
TypesMachine language and assembly languagePython, Java, C#, JavaScript, etc.
Hardware dependenceMachine code is processor-specific; assembly is usually tied to a processor family.Generally more portable, depending on the language and runtime.
TranslationMachine code runs directly; assembly is translated by an assembler.Usually compiled, interpreted or run through a virtual machine.
ReadabilityBinary machine code is difficult to read; assembly uses symbolic instructions.Uses more human-readable words and structures.
Programming complexityMore detail about hardware and memory is often required.Often quicker to write, debug and maintain.
Typical useFirmware, device drivers and hardware-specific routines.Websites, applications, data analysis and general software.
Conclusion: Low-level languages offer close hardware control, while high-level languages generally improve programmer productivity and portability. The best choice depends on the task.

Question 7 · Evaluating

Reliability and Security of Vision-Input vs Voice-Recognition Devices

Face recognition and voice recognition are biometric technologies. Their reliability depends on sensor quality, environmental conditions, system design and how the system handles errors. Neither should be treated as perfectly accurate.

IssueVision / facial recognitionVoice recognition
Environmental effectsLighting, camera angle, masks, image quality and changes in appearance can affect results.Background noise, distance, illness, microphone quality and changes in voice can affect results.
Spoofing riskPhotos, video or masks may threaten systems without effective liveness checks.Recordings or synthetic voices may threaten systems without effective anti-spoofing measures.
PrivacyMay capture faces of people who did not intend to enroll or authenticate.May record bystanders or sensitive spoken information.
Operational reliabilityCamera obstruction or poor placement can cause failures.Noise, shared spaces and quiet-speaking users can cause failures.
MitigationUse liveness detection, secure templates, access limits and a fallback method.Use anti-spoofing, secure templates, noise-aware design and a fallback method.

Recommendations for public environments

  • Do not rely on one biometric method as the only way to access an important service.
  • Use multi-factor authentication where appropriate, such as a card plus a PIN or another independent factor.
  • Encrypt stored biometric templates, restrict staff access, audit use and define retention periods.
  • Offer a non-biometric alternative and a clear process for false rejections.
  • Test performance across different users and real operating conditions before deployment.
Conclusion: A biometric system should be selected after risk assessment and testing. Strong privacy controls, liveness checks, secure storage and an accessible fallback are essential in noisy or publicly exposed settings.
Question 8 · Creating

Accessible Hands-Free Workstation for a Visually Impaired User

The goal is to provide a workstation that can be operated without relying on sight or precise hand movements. It should offer spoken feedback, keyboard alternatives and a way to obtain help when needed.

Proposed system components

  • Voice recognition: Allows users to dictate text and issue supported commands.
  • Screen reader: Reads interface text, menus, notifications and document content aloud.
  • Speech output / voice synthesizer: Converts system text into spoken feedback through headphones or speakers.
  • Tactile keyboard or braille display: Offers tactile input or refreshable Braille output for users who prefer it.
  • Accessible operating system and apps: Use labelled controls, keyboard navigation, clear focus indicators and meaningful headings.
  • Optional scanner with OCR: Converts printed documents into text that a screen reader can read.
  • Privacy and safety: Provide headphone support, a microphone mute control, secure sign-in and a non-voice fallback.
Integrated accessible workstation
User inputVoice commands · microphone · tactile keyboard
↓
Computer + accessible softwareVoice recognition · keyboard navigation · OCR
↓
Feedback to userScreen reader · speech synthesizer · Braille display

How it works

  1. The user signs in using an accessible authentication method.
  2. The user speaks a command or enters text using a tactile keyboard.
  3. The operating system and application process the command, with visible focus and accessible labels available to assistive software.
  4. The screen reader announces the current control and results; a Braille display can provide tactile text where available.
  5. If voice input fails, the user can switch to keyboard navigation or request assistance without losing work.

Accessibility and evaluation

  • Provide training and allow users to customize speech rate, voice, volume and keyboard shortcuts.
  • Minimize background noise and make microphone status obvious.
  • Test the workstation with intended users and common tasks, not only with technical benchmarks.
  • Keep software updated and protect personal information, especially voice recordings and scanned documents.
Conclusion: Combining voice input, screen-reading software, speech output and tactile options provides flexible access. Multiple input and output methods make the workstation more dependable and inclusive.
